# Narrow recurring prospective player-snapshot authorization

**Status: implemented; the exact narrow policy has been approved, with activation controlled by the separately installed local-development authorization file.** Ordinary permitted raw release synchronization remains separate. The handler never creates an authorization file or interprets an approved one-time backfill as recurring authority.

The fixed reviewed policy exported by `src/ingestion/open-data/recurring-snapshots.ts` has SHA-256 fingerprint:

`cb8dfe386dba85c628276271b47fb249b6a8a3d7fb9729e448742e0058bea61b`

The policy allows only the existing nflverse/SportsDataverse NFL/NBA/NHL roster and four-sport injury release IDs, with their exact registered URLs, data-license references, byte limits and categories. It is restricted to season start year 2026, existing explicitly resolved real canonical players/teams/seasons and approved prospective player facts. The normalizer's generic POSITION, TEAM_ASSIGNMENT, AVAILABILITY and explicit NFL ROOKIE facts are allowed. Dedicated NBA position snapshots are allowed only from the direct NBA roster product under the approved granular/family mapping; the alternate ESPN roster cannot overwrite those positions. Recovered MLB aggregates, calendars, statistics, new identities/teams, ownership, scoring and financial writes are outside scope.

After an explicit approval only, the operator may create the ignored file `data/operations/recurring_snapshot_authorization.json` containing exactly `enabled:true`, the approved `policyFingerprint` and the actual `approvedAt` instant. Absence, malformed/disabled authorization, changed fingerprint or inapplicable approval time fails closed. The default loader also requires localhost/127.0.0.1, the normal PostgreSQL port, database `fantasy_evolution` and no custom schema; a workspace development grant cannot authorize production or disposable test databases. Tests can inject authorization only after the existing authorized disposable-schema guard passes; there is no unguarded production override.

Each promoted source body must have its **first actual receipt at or after approval**. Re-fetching an old body, changing its file mtime or inspecting it again does not bring an old substantial target into scope. Roster bodies must be within seven days and injury bodies within 48 hours. Expiry/date precision remains the existing reviewed normalizer's semantics; local/source/snapshot/exact times stay separate. Application is prospective at actual processing/decision time; unknown professional effective/publication times remain unknown.

The lease-owning caller supplies exact raw bytes, transport metadata and the immutable normalization-queue body/file. The handler verifies the raw SHA, source identity, queue/candidate fingerprint, chronology, maximum 15,000 facts per product/cycle and current season before canonical writes. Generic facts are re-derived from the exact CSV/Parquet bytes and compared against the candidate semantics. Dedicated NBA facts are checked against the unique direct-ID source row and original position. A self-consistent forged queue fingerprint does not authorize a different source designation. Unknown/conflicted/retracted identities or unresolved teams are held locally; no identity, team or alias is manufactured. An existing stream may not be reassigned to a different canonical actor.

`processRecurringSnapshots(tx,input,at,options)` runs inside the caller's lease-fenced transaction and delegates accepted facts to the existing immutable ingestion path. Repeated copies use database observation/decision receipts for idempotence. It returns disabled/pending/quarantined or processed counts, local hold reasons and an optional receipt path/content. **The caller publishes that diagnostic receipt only after transaction commit.** A receipt marked `transactionCommitRequired:true` cannot authorize a replay skip; a transaction may still roll back. Root source leases, retry and request budgets remain outside this handler.

Four isolated integration cases are prepared: explicit authorization/freshness/old-body exclusion; existing-only prospective facts and zero-addition replay; raw/queue/provider/season tamper rejection; and direct NBA family evidence without LISTED rows or retroactive grants. No development promotion or database test was performed by this workstream. Controlled deployment/validation and installation of the approved authorization file remain operator-owned activation steps; this workstream did not install that file.

Dedicated NBA same-revision integrity conflicts now retain a blocking marker only for the safely proven prior canonical actor, and preserve historical as-of eligibility. Generic same-revision conflicts are also enforced: actor/season/facet-bound conflict receipts block current position/count grants, report team CONFLICT and withhold IR/rookie eligibility. A shared stream-head reducer and one batched conflict read preserve prior as-of results; a later accepted higher revision restores the applicable evidence. Rejected contradictory observations create no invented health, retraction, team or rookie facts and cannot reassign a canonical actor. No new provider-arbitration rule is inferred from this narrow authorization mechanism. Omitted injury records never become healthy, missing profiles never become retired, and missing players never become rookies.

Immutable first source receipts are scoped by product URL and raw SHA, retaining matching auxiliary legacy receipts and corrected provenance separately. Returning an old body after another body (A→B→A), or losing the first atomic publication race, cannot reset that body’s first trustworthy receipt or freshness. Frozen source manifests and legacy proof files remain untouched.
